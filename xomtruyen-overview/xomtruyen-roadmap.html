🔴 Sprint 1: MONETIZATION — Nạp xu & Mua gói VIP

📅 Tuần 1-2 | ⏱️ ~14 ngày | 🎯 User có thể trả tiền và đọc truyện VIP

Mục tiêu Sprint

Hoàn thành flow: User chọn gói → Thanh toán → Nhận xu/VIP → Đọc chương bị khóa

Kiến trúc thanh toán

User (Client Web/Mobile)
→ Chọn gói xu / VIP
→ POST /api/payment/top-up hoặc /subscribe
→ API tạo Transaction (status=Pending)
→ Trả về PaymentUrl (MoMo/VNPay) hoặc QR chuyển khoản
→ User thanh toán trên cổng
→ Cổng gọi Webhook → POST /api/payment/callback
→ API verify chữ ký → Cộng xu / Kích hoạt VIP
→ Transaction status = Completed
→ Client poll hoặc redirect → Hiển thị thành công

Luồng thanh toán MoMo (chi tiết kỹ thuật)

// 1. Client gọi API
POST /api/payment/top-up
Body: { packageId: "pack_120", paymentMethod: "Momo", returnUrl: "https://xomtruyen.com/wallet" }

// 2. Backend tạo Transaction (Pending) → Gọi MoMo API
POST https://payment.momo.vn/v2/gateway/api/create
Body: {
  partnerCode: "MOMO_PARTNER",
  requestId: "{transactionId}",
  amount: 20000,
  orderId: "{transactionId}",
  orderInfo: "Nap 120 xu XomTruyen",
  redirectUrl: "https://xomtruyen.com/wallet?status=success",
  ipnUrl: "https://api.xomtruyen.com/api/payment/callback/momo",
  requestType: "payWithMethod",
  extraData: base64({userId, packageId, coinAmount})
}

// 3. MoMo trả về payUrl → Backend trả cho Client
Response: { paymentUrl: "https://payment.momo.vn/...", orderId: "..." }

// 4. User thanh toán → MoMo gọi ipnUrl
POST /api/payment/callback/momo
→ Verify HMAC-SHA256 signature
→ Nếu hợp lệ: cộng xu cho user, update Transaction status = Completed

// 5. Client redirect về returnUrl, gọi GET /wallet để hiển thị số dư mới

Thiết kế Full-text Search (PostgreSQL)

-- Migration: Thêm tsvector column
ALTER TABLE "Publications" ADD COLUMN "SearchVector" tsvector;

-- Populate
UPDATE "Publications" 
SET "SearchVector" = to_tsvector('simple', 
    coalesce("Title",'') || ' ' || 
    coalesce("Author",'') || ' ' || 
    coalesce("Description",'')
);

-- Index
CREATE INDEX idx_publications_search ON "Publications" USING GIN("SearchVector");

-- Query (trong Repository)
SELECT * FROM "Publications"
WHERE "SearchVector" @@ plainto_tsquery('simple', @keyword)
   OR "Title" ILIKE '%' || @keyword || '%'
ORDER BY ts_rank("SearchVector", plainto_tsquery('simple', @keyword)) DESC
LIMIT @pageSize OFFSET @offset;

Lời khuyên chiến lược

1. MVP Monetization trước: Nếu MoMo/VNPay chưa duyệt được, làm chuyển khoản thủ công + Admin nạp xu. Đừng để payment gateway block toàn bộ Sprint 1.

2. Content là vua: Song song với code, hãy upload 20-30 truyện hay lên hệ thống. Platform không có content = không ai dùng.

3. Responsive web > Mobile app: Nếu Sprint 4 bị thiếu thời gian, ưu tiên responsive web hơn mobile app. 80% user đọc truyện trên điện thoại qua browser.

4. Feedback sớm: Sau Sprint 2, mời 5-10 người thử đọc truyện. Feedback thật sẽ định hướng Sprint 3-4 tốt hơn.

PHASE 3: Scale & Polish (Tháng 4 — ~4 tuần)

🎯 Performance, Analytics, Multi-device sync, Content pipeline tự động

Tính năngEffortMô tả chi tiết
CDN cho ảnh truyện 3-4 ngày Tích hợp Cloudflare R2 hoặc BunnyCDN. Ảnh serve qua edge server gần user → load nhanh gấp 5-10x. API vẫn upload local → sync lên CDN.
Image Optimization Pipeline 2 ngày Auto-resize theo device (mobile nhỏ hơn desktop). WebP + AVIF fallback. Lazy progressive loading.
Multi-device Reading Sync 2 ngày Đọc trên laptop → mở mobile → tự động ở đúng chương + trang. Sync qua API reading position.
Analytics Dashboard (Admin) 3-4 ngày DAU/MAU, retention rate, top truyện hot, revenue chart, user growth. Dùng chart.js/recharts.
Recommendation Engine cơ bản 3 ngày Collaborative filtering đơn giản: "User đọc truyện A cũng đọc B". Dựa trên ReadingHistory + Category overlap.
Offline Reading (Mobile) 3-4 ngày Download chương về device (Capacitor filesystem). Đọc không cần internet. Sync khi online lại.
Admin — Bulk Content Import 2 ngày Import hàng loạt truyện từ folder/CSV. Auto-detect chapters từ cấu trúc file. Schedule publish.
Caching Layer (Redis) 2 ngày Cache: list publications, hot chapters, user session. Giảm DB load 60-70%.
API Versioning 1 ngày /api/v1/ prefix. Cho phép update API mà không break mobile app đang dùng version cũ.
Health Monitoring & Alerts 1 ngày Uptime Robot/BetterStack monitor. Alert Telegram/Discord khi server down. Auto-restart service.
