🔐 3. GAP: Authentication & Authorization

Vấn đề phát hiện:

  • File userApi.ts có auth interceptor nhưng đã bị comment out:
// Uncomment when you implement authentication
// const token = localStorage.getItem('token');
// if (token) {
//   config.headers.Authorization = `Bearer ${token}`;
// }
  • Trang /login có form UI nhưng không có logic submit — nút đăng nhập chỉ là <Link to="/"> (redirect thẳng về Dashboard)
  • Không có Route Guard / ProtectedRoute — bất kỳ ai truy cập URL đều vào được admin
  • Không có role-based access trong frontend
  • Backend controllers chưa bật [Authorize] attribute

✅ Cần làm:

  1. Login page: gọi POST /api/auth/login, lưu JWT token vào localStorage
  2. Uncomment auth interceptor — gắn Bearer token vào mọi request
  3. Tạo ProtectedRoute component — redirect về /login nếu không có token
  4. Tạo AuthContext — lưu user info + role hiện tại
  5. Backend: bật [Authorize(Roles = "Admin")] cho admin controllers
  6. Auto-refresh token khi sắp hết hạn (optional nhưng nên có)

Code cần thêm

File mới: src/contexts/AuthContext.tsx

// AuthContext quản lý: login, logout, user info, role check
// Lưu token vào localStorage
// Decode JWT để lấy role claim
// Expose: isAuthenticated, user, login(), logout()

File mới: src/components/layout/ProtectedRoute.tsx

    const token = localStorage.getItem('accessToken');
    if (token) {

    }
    return config;
});

👮 11. GAP: Phân quyền Role-based

Vấn đề:

  • Backend JWT token không có Role claim (hoặc có nhưng chưa sử dụng)
  • User model không có field Role rõ ràng (chỉ có Provider: Local/Google)
  • Admin controllers chưa bật [Authorize]
  • Frontend không check role → bất kỳ user nào login cũng vào được admin panel

✅ Cần làm:

  1. DB: Thêm column Role vào Users table (hoặc tạo bảng Roles riêng). Values: "User", "Admin", "Editor"
  2. Backend Auth: Khi generate JWT, include claim "role": "Admin"
  3. Backend Controllers: Thêm [Authorize(Roles = "Admin")] vào tất cả admin endpoints
  4. Frontend: Decode JWT, check role === "Admin" trước khi cho truy cập
  5. Admin UI: Trong trang Users, thêm dropdown đổi Role cho user

📋 12. Danh sách Task chi tiết (cho AI thực hiện)

Dưới đây là danh sách task copy-paste cho AI đọc và thực hiện. Mỗi task có đủ context để AI có thể code mà không cần hỏi thêm.

TASK GROUP A: Authentication (Backend + Frontend)

Task A1: Backend — Thêm Role vào User model + JWT

Dự án: xomtruyen backend (.NET 9)
Yêu cầu:
1. Thêm property "Role" (string, default "User") vào entity User
2. Migration: ALTER TABLE "Users" ADD COLUMN "Role" varchar(20) DEFAULT 'User'
3. Seed admin user: UPDATE "Users" SET "Role" = 'Admin' WHERE Email = 'admin@xomtruyen.com'
4. Khi generate JWT token (trong AuthService/TokenService): 
   - Thêm claim: new Claim(ClaimTypes.Role, user.Role)
5. Thêm [Authorize(Roles = "Admin")] vào:
   - AdminComicChapterController
   - Tất cả controllers có prefix "Admin"
   - PUT/DELETE /api/users
   - ManagerDB endpoints

Task A2: Frontend Admin — Login thật + Protected Route

Dự án: xomtruyen-admin (React + TypeScript + Vite)
Base URL API: http://localhost:5172/api
Files cần sửa/tạo:
1. TẠO: src/contexts/AuthContext.tsx
   - State: user, accessToken, isAuthenticated
   - Methods: login(email, password), logout(), refreshToken()
   - Login gọi: POST /api/auth/login → body { email, password }
   - Response có: { accessToken, refreshToken, user: { id, email, role } }
   - Lưu accessToken + refreshToken vào localStorage
   - Decode JWT để lấy role (dùng jwt-decode library)
   
2. TẠO: src/components/layout/ProtectedRoute.tsx
   - Nếu !isAuthenticated → Navigate to="/login"

Logic bổ sung: Sau khi create/delete review → recalculate AverageRating trên Publications:
UPDATE "Publications" SET "AverageRating" = (SELECT AVG("Rating") FROM "Reviews" WHERE "PublicationId" = @pubId) WHERE "Id" = @pubId
