1. Kiến trúc Deploy

✅ Khuyến nghị: Tách riêng Frontend (Vercel) và Backend (Laptop/VPS)

┌─────────────────┐ ┌──────────────────────┐

│ Vercel (CDN) │ │ Laptop / VPS │

│ │ HTTP │ │

│ React Frontend │ ──────► │ .NET API + Database │

│ (Static Files) │ │ │

└─────────────────┘ └──────────────────────┘

Ưu điểm khi tách riêng

  • Frontend được Vercel tối ưu CDN, load nhanh toàn cầu
  • Deploy frontend cực nhanh, chỉ cần push code
  • Không ảnh hưởng backend khi update UI và ngược lại
  • Free tier của Vercel khá rộng rãi cho project cá nhân
  • Scale độc lập từng phần

Lưu ý cần xử lý

  • Backend cần có IP public hoặc dùng tunnel (ngrok, Cloudflare Tunnel) để Vercel gọi được API
  • Cấu hình CORS cho phép domain Vercel gọi API
  • Biến môi trường VITE_API_URL trỏ đúng về server backend

So sánh

Tách riêng Khuyến nghị

  • CDN tốc độ cao
  • Deploy độc lập
  • Scale linh hoạt
  • Cần xử lý CORS
  • Backend cần public IP

Để chung OK

  • Đơn giản, không lo CORS
  • Dễ debug
  • Laptop phải chạy 24/7
  • Không có CDN
  • Scale khó hơn
💡 Giải pháp expose backend:
• Dev/Demo: Dùng Cloudflare Tunnel (miễn phí) hoặc ngrok
• Production: Thuê VPS nhỏ (~$5/tháng) để đặt backend

2. Cấu trúc Repository

Cả hai cách đều ổn. Với project cá nhân, chọn cách nào thoải mái quản lý hơn.

Monorepo (1 repo)

xomtruyen/
├── xom-truyen/    ← frontend
├── server/        ← backend
└── README.md
  • Quản lý 1 chỗ
  • Dễ theo dõi lịch sử
  • Vercel hỗ trợ build từ thư mục con

Multi-repo (2 repo)

xomtruyen-client/  ← repo frontend
xomtruyen-server/  ← repo backend
  • Git history sạch
  • Deploy Vercel đơn giản hơn
  • Tách biệt rõ ràng

Deploy Vercel từ monorepo

Nếu giữ chung 1 repo, cấu hình trên Vercel:

  • Root Directory: xom-truyen
  • Build Command: npm run build
  • Output Directory: dist

3. Quản lý Secret trong .NET Backend

Development: User Secrets

Không commit lên git, lưu riêng trên máy:

dotnet user-secrets init
dotnet user-secrets set "Jwt:SecretKey" "your-secret-key"
dotnet user-secrets set "ConnectionStrings:Default" "Server=...;Password=..."

Truy cập trong code:

var jwtKey = builder.Configuration["Jwt:SecretKey"];

Production: Environment Variables

  • Set biến môi trường trên server/VPS
  • Hoặc dùng dịch vụ: Azure Key Vault, AWS Secrets Manager, HashiCorp Vault

File appsettings.json (commit được)

Chỉ chứa config không nhạy cảm:

{
  "Jwt": {
    "Issuer": "xomtruyen",
    "ExpireMinutes": 60
  },
  "ConnectionStrings": {
    "Default": ""
  }
}
⚠️ KHÔNG BAO GIỜ để password, secret key, connection string thật trong file commit lên git!

4. Quản lý Secret trong React/Vite Frontend

File .env (KHÔNG commit)

VITE_API_URL=http://localhost:5000/api
VITE_GOOGLE_CLIENT_ID=xxx

Truy cập trong code:

const apiUrl = import.meta.env.VITE_API_URL;

File .env.example (commit được)

Chứa tên biến nhưng không có giá trị thật:

# .env.example
VITE_API_URL=
VITE_GOOGLE_CLIENT_ID=

Trên Vercel

Vào Project Settings → Environment Variables, thêm các biến ở đó. Vercel inject khi build.

⚠️ Quan trọng: Mọi thứ ở frontend đều PUBLIC (user có thể thấy trong browser). Chỉ để API URL, public key. KHÔNG để private key, secret ở frontend!

Nguyên tắc chung

Quy tắc Giải thích
Không commit secret lên git Dù repo private cũng không nên
.gitignore chứa .env Tránh lộ khi push
Frontend không giữ secret thật Client code ai cũng đọc được
Secret thật chỉ ở backend JWT secret, DB password → chỉ server
Dùng .env.example Document các biến cần config

5. ✅ Checklist việc cần làm

Frontend (React/Vite)

  • Kiểm tra .env đã nằm trong .gitignore
  • Tạo file .env.example chứa tên biến (không có giá trị)
  • Đảm bảo chỉ dùng VITE_ prefix cho biến môi trường
  • Connect repo với Vercel
  • Cấu hình Environment Variables trên Vercel
  • Set Root Directory nếu dùng monorepo

Backend (.NET)

  • Setup User Secrets cho development
  • Đảm bảo appsettings.Development.json trong .gitignore
  • Cấu hình CORS cho phép domain Vercel
  • Setup Cloudflare Tunnel hoặc ngrok để expose API
  • Dùng Environment Variables cho production

Repository

  • Quyết định monorepo hay multi-repo
  • Review lại .gitignore cả frontend lẫn backend
  • Kiểm tra không có secret nào đã commit trong git history
