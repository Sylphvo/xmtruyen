🔔 Module 1: Notifications / Thông báo & Tin tức

High Priority NEW — Chưa có trong DB

Lý do: Mobile app (xomtruyen-app) có page Notifications.tsx với 2 tab "Orders" và "News". Client web Header có icon bell thông báo. Nhưng backend không có model/API nào cho notifications.

Database Schema cần tạo

-- Table: Notifications
CREATE TABLE "Notifications" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "UserId" UUID REFERENCES "Users"("Id"),       -- NULL = broadcast to all
    "Title" VARCHAR(200) NOT NULL,
    "Message" TEXT NOT NULL,
    "Type" VARCHAR(50) NOT NULL,                   -- 'system', 'chapter_update', 'payment', 'promotion'
    "ReferenceId" UUID,                            -- Link to related entity (publicationId, transactionId...)
    "ReferenceType" VARCHAR(50),                   -- 'publication', 'transaction', 'chapter'
    "IsRead" BOOLEAN DEFAULT FALSE,
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

-- Index
CREATE INDEX idx_notifications_user ON "Notifications"("UserId", "IsRead", "CreatedAt" DESC);

Backend Model

// Models/Notification.cs
public class Notification
{
    public Guid Id { get; set; }
    public Guid? UserId { get; set; }              // null = broadcast
    public User? User { get; set; }
    public string Title { get; set; } = null!;
    public string Message { get; set; } = null!;
    public string Type { get; set; } = null!;      // system, chapter_update, payment, promotion
    public Guid? ReferenceId { get; set; }
    public string? ReferenceType { get; set; }
    public bool IsRead { get; set; } = false;
    public DateTime? CreatedAt { get; set; }
}

API Endpoints

Client (cho user)

GET    /api/notifications?page=1&pageSize=20      [Authorize]
       → List thông báo của user hiện tại (bao gồm broadcast)
GET    /api/notifications/unread-count              [Authorize]
       → { count: 5 }
PATCH  /api/notifications/{id}/read                [Authorize]
       → Mark 1 notification as read
PATCH  /api/notifications/read-all                 [Authorize]
       → Mark all as read

Admin

GET    /api/admin/notifications?type=&page=1       [Admin]
       → List tất cả notifications đã gửi
POST   /api/admin/notifications                    [Admin]
       Body: { title, message, type, targetUserId (optional), targetAll: true }
       → Tạo notification (gửi cho 1 user hoặc broadcast all)
POST   /api/admin/notifications/broadcast          [Admin]
       Body: { title, message, type }
       → Gửi cho tất cả users
DELETE /api/admin/notifications/{id}               [Admin]

Admin UI — Trang /notifications

  • Tab 1: "Đã gửi" — List notifications đã tạo (filter by type)
  • Tab 2: "Tạo mới" — Form: Title, Message, Type (dropdown), Target (All users / Specific user)
  • Auto-trigger: Khi có chương mới → tự tạo notification cho users đã favorite truyện đó

Luồng tự động

Trigger tự động (không cần admin bấm): 1. User nạp xu thành công → Notification: "Nạp 120 xu thành công!" 2. Truyện yêu thích có chương mới → Notification: "Đấu Phá Thương Khung có chương 156 mới!" 3. Gói VIP sắp hết hạn (3 ngày) → Notification: "Gói VIP của bạn sắp hết hạn" 4. Admin broadcast khuyến mãi → Notification cho all users

🎫 Module 2: Promotions / Khuyến mãi & Coupon

High Priority NEW — Chưa có trong DB

Lý do: Mobile app có page Offers.tsx hiển thị các coupon (50% OFF, 23% OFF) với color codes. Cũng có PromotionDetail.tsx. Nhưng tất cả là mock data hardcoded, không có backend.

Database Schema

-- Table: Promotions
CREATE TABLE "Promotions" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "Code" VARCHAR(50) UNIQUE NOT NULL,            -- Mã coupon: XOMVIP50, TETMOI2027
    "Title" VARCHAR(200) NOT NULL,
    "Description" TEXT,
    "DiscountType" VARCHAR(20) NOT NULL,           -- 'percentage', 'fixed_coin', 'free_chapter'
    "DiscountValue" INT NOT NULL,                  -- 50 (50%), hoặc 100 (100 xu)
    "MinPurchase" INT DEFAULT 0,                   -- Đơn hàng tối thiểu (xu)
    "MaxUsage" INT,                                -- Số lần dùng tối đa (null = unlimited)
    "UsageCount" INT DEFAULT 0,                    -- Đã dùng bao nhiêu lần
    "MaxPerUser" INT DEFAULT 1,                    -- Mỗi user dùng tối đa bao nhiêu lần
    "StartDate" TIMESTAMP NOT NULL,
    "EndDate" TIMESTAMP NOT NULL,
    "IsActive" BOOLEAN DEFAULT TRUE,
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

-- Table: UserPromotionUsages (tracking)
CREATE TABLE "UserPromotionUsages" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "UserId" UUID REFERENCES "Users"("Id"),
    "PromotionId" UUID REFERENCES "Promotions"("Id"),
    "UsedAt" TIMESTAMP DEFAULT NOW()
);

API Endpoints

Client

GET    /api/promotions/active                      → List promotions đang active (cho user xem)
POST   /api/promotions/apply                       [Authorize]
       Body: { code: "XOMVIP50" }
       → Validate & apply: trả xu bonus hoặc giảm giá
       Response: { success: true, discountAmount: 50, message: "Áp dụng thành công!" }

Admin

GET    /api/admin/promotions?isActive=&page=1      → List tất cả promotions
POST   /api/admin/promotions                       → Create promotion
PUT    /api/admin/promotions/{id}                  → Update
PATCH  /api/admin/promotions/{id}/toggle           → Active/Inactive
DELETE /api/admin/promotions/{id}
GET    /api/admin/promotions/{id}/usage            → Xem ai đã dùng coupon này

Admin UI — Trang /promotions

  • Table: Code, Title, Type (badge), Value, Usage (x/max), Start-End date, Status, Actions
  • Modal tạo/sửa: Code (auto-gen hoặc tự nhập), Title, Description, Type dropdown, Value, Min purchase, Max usage, Date range
  • Analytics: Tổng coupon đã dùng, top coupon phổ biến, doanh thu từ promotions

🖼️ Module 3: Banner & Homepage CMS

High Priority NEW — Chưa có trong DB

Lý do: Client web trang chủ có các sections (Mới nhất, Đề xuất, Độc quyền, Slider) nhưng hiện tại query cố định từ API. Mobile app có promo banners. Admin không thể customize trang chủ mà không sửa code.

Database Schema

-- Table: Banners
CREATE TABLE "Banners" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "Title" VARCHAR(200) NOT NULL,
    "ImageUrl" VARCHAR(500) NOT NULL,
    "LinkUrl" VARCHAR(500),                         -- Click banner → đi đâu
    "LinkType" VARCHAR(50),                        -- 'publication', 'category', 'external', 'promotion'
    "ReferenceId" UUID,                            -- publicationId / categoryId
    "Position" VARCHAR(50) NOT NULL,               -- 'hero', 'sidebar', 'mobile_top', 'popup'
    "OrderIndex" INT DEFAULT 0,
    "IsActive" BOOLEAN DEFAULT TRUE,
    "StartDate" TIMESTAMP,
    "EndDate" TIMESTAMP,
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

-- Table: HomeSections (quản lý layout trang chủ)
CREATE TABLE "HomeSections" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "Title" VARCHAR(200) NOT NULL,                 -- "Truyện Đề Cử", "Mới Cập Nhật", ...
    "SectionType" VARCHAR(50) NOT NULL,            -- 'recommended', 'latest', 'exclusive', 'category', 'custom'
    "QueryType" VARCHAR(50),                       -- 'auto' (query DB) hoặc 'manual' (chọn tay)
    "QueryParams" TEXT,                            -- JSON: { "categoryId": "...", "limit": 10, "sortBy": "viewCount" }
    "ManualPublicationIds" TEXT,                   -- JSON array nếu QueryType = 'manual'
    "OrderIndex" INT DEFAULT 0,
    "IsActive" BOOLEAN DEFAULT TRUE,
    "DisplayStyle" VARCHAR(50) DEFAULT 'grid'      -- 'grid', 'slider', 'list', 'featured'
);

        { title: "Mới Cập Nhật", displayStyle: "grid", publications: [...] },

Admin UI — 2 trang

Trang /banners

  • Grid/List banners: Ảnh thumbnail, Title, Position, Link, Active, Date range
  • Upload ảnh banner + chọn link đến (truyện / thể loại / URL ngoài)

Trang /home-sections

  • List sections trang chủ (drag-drop reorder)
  • Mỗi section: Title, Type, Display style, Books included

💰 Module 5: Coin Packages / Gói nạp xu

Critical Priority NEW — Chưa có trong DB

Lý do: Roadmap đề cập gói xu (10K=50xu, 20K=120xu...) nhưng chỉ nằm trong document. Backend không có table CoinPackage. Khi user muốn nạp xu, client cần biết có bao nhiêu gói, giá bao nhiêu → phải có API trả về danh sách gói.

Database Schema

CREATE TABLE "CoinPackages" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "Name" VARCHAR(100) NOT NULL,                  -- "Gói Starter", "Gói Tiết Kiệm"

    "IsPopular" BOOLEAN DEFAULT FALSE,             -- Badge "Hot" trên UI
    "IsActive" BOOLEAN DEFAULT TRUE,
    "OrderIndex" INT DEFAULT 0,
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

API Endpoints

// Public (client hiển thị cho user chọn mua)
GET    /api/coin-packages                          → List gói active, sorted by OrderIndex

// Admin
GET    /api/admin/coin-packages                    → List all (kể cả inactive)
POST   /api/admin/coin-packages                    → Create package
PUT    /api/admin/coin-packages/{id}               → Update (đổi giá, đổi bonus)
PATCH  /api/admin/coin-packages/{id}/toggle        → Active/Inactive
DELETE /api/admin/coin-packages/{id}
PATCH  /api/admin/coin-packages/reorder            → Reorder display

Admin UI — Trang /coin-packages

  • Table/Card: Tên gói, Xu nhận, Bonus, Giá VNĐ, Popular badge, Status, Actions
  • Form: Name, CoinAmount, BonusCoins, PriceVND, IsPopular checkbox
  • Preview: Hiển thị giống UI mà user sẽ thấy trên client

⚠️ Lưu ý quan trọng

Module này PHẢI CÓ trước khi làm payment gateway (Sprint 1). Luồng nạp xu: User chọn CoinPackage → thanh toán → API verify → cộng coins. Nếu không có table CoinPackage, client không biết hiển thị gì.

🚨 Module 6: Report / Báo cáo vi phạm

Medium Priority NEW — Chưa có trong DB

Lý do: Platform có reviews, comments (sẽ thêm). Khi có user-generated content → cần cơ chế report nội dung vi phạm. Nếu không có, admin phải tự đọc từng review để tìm vi phạm — không scale được.

Database Schema

CREATE TABLE "Reports" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "ReporterId" UUID REFERENCES "Users"("Id"),    -- Ai báo cáo
    "TargetType" VARCHAR(50) NOT NULL,             -- 'review', 'comment', 'publication', 'user'
    "TargetId" UUID NOT NULL,                      -- ID của entity bị report
    "Reason" VARCHAR(100) NOT NULL,                -- 'spam', 'offensive', 'copyright', 'misinformation'
    "Description" TEXT,                            -- Mô tả thêm
    "Status" VARCHAR(50) DEFAULT 'pending',        -- 'pending', 'reviewed', 'resolved', 'dismissed'
    "AdminNote" TEXT,                              -- Admin ghi chú khi xử lý
    "ResolvedBy" UUID,
    "ResolvedAt" TIMESTAMP,
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

Admin UI — Trang /reports

  • Table: Reporter, Target (link to review/user/publication), Reason (badge), Status, Date
  • Filter: by Status (Pending/Resolved/Dismissed), by Type, by Date
  • Actions: View target content, Resolve (xóa content + ban user nếu cần), Dismiss (bỏ qua)
  • Badge count "Pending reports" trên sidebar
