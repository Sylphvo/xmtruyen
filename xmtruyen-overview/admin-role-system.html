📊 4. Cấp bậc & Kế thừa quyền

CẤP BẬC ROLE (từ cao → thấp): 👑 SuperAdmin (Level 100) │ ├── Có TẤT CẢ quyền ├── Assign/Remove mọi role └── Truy cập mọi module │ ┌────────┴─────────────────────────────┐ │ │ 📝 Editor (Level 50) 🛡️ Moderator (Level 40) │ │ ├── Content management ├── Community management ├── Crawler, Translation ├── Reviews, Reports ├── Audiobook, Banners ├── Ban/Unban users ├── Promotions └── Notifications │ 🌐 Translator (Level 30) │ ├── Translation review only ├── Edit text blocks └── Approve/Reject translations │ ┌────┴────────────────────────────────┐ │ │ ✍️ Author (Level 20) 👤 User (Level 10) │ │ ├── Đăng truyện riêng ├── Đọc truyện ├── Quản lý tác phẩm mình ├── Mua xu/VIP └── Xem analytics mình ├── Bookmark, Review └── Cộng đồng │ 👻 Guest (Level 0) │ └── Đọc giới hạn only QUY TẮC: • 1 user có thể có NHIỀU roles (VD: vừa là Editor vừa là Author) • Role cao hơn bao gồm quyền role thấp hơn? → KHÔNG (mỗi role độc lập) • SuperAdmin có tất cả quyền (bypass check) • User phải đăng nhập mới có role (Guest = chưa đăng nhập)

🗄️ 5. Database Schema

-- ═══════════════════════════════════════════════════════════
-- ROLE-BASED ACCESS CONTROL (RBAC) TABLES
-- ═══════════════════════════════════════════════════════════

-- 1. Roles (định nghĩa các role)
CREATE TABLE "Roles" (
    "Id" INT PRIMARY KEY,
    "Name" VARCHAR(50) UNIQUE NOT NULL,            -- 'SuperAdmin', 'Editor', 'Translator', 'Moderator', 'Author', 'User'
    "DisplayName" VARCHAR(100) NOT NULL,           -- 'Quản trị viên', 'Biên tập viên', ...
    "Description" TEXT,
    "Level" INT DEFAULT 0,                         -- Hierarchy level (100, 50, 40, 30, 20, 10)
    "Color" VARCHAR(20),                           -- Badge color: '#ff4444', '#ff9800', ...
    "IsSystemRole" BOOLEAN DEFAULT TRUE,           -- TRUE = không cho xóa
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

-- 2. UserRoles (nhiều-nhiều: 1 user có nhiều roles)
CREATE TABLE "UserRoles" (
    "UserId" UUID NOT NULL REFERENCES "Users"("Id") ON DELETE CASCADE,
    "RoleId" INT NOT NULL REFERENCES "Roles"("Id") ON DELETE CASCADE,
    "AssignedBy" UUID,                             -- Ai assign role này
    "AssignedAt" TIMESTAMP DEFAULT NOW(),
    "ExpiresAt" TIMESTAMP,                         -- NULL = vĩnh viễn, có giá trị = tạm thời
    PRIMARY KEY ("UserId", "RoleId")
);

-- 3. Permissions (quyền cụ thể)
CREATE TABLE "Permissions" (
    "Id" VARCHAR(100) PRIMARY KEY,                 -- 'publications.create', 'users.ban', 'transactions.view'
    "Module" VARCHAR(50) NOT NULL,                 -- 'publications', 'users', 'transactions', 'translation', ...
    "Action" VARCHAR(50) NOT NULL,                 -- 'create', 'read', 'update', 'delete', 'publish', 'approve'
    "DisplayName" VARCHAR(200) NOT NULL,
    "Description" TEXT
);

-- 4. RolePermissions (role nào có permission nào)
CREATE TABLE "RolePermissions" (
    "RoleId" INT NOT NULL REFERENCES "Roles"("Id") ON DELETE CASCADE,
    "PermissionId" VARCHAR(100) NOT NULL REFERENCES "Permissions"("Id") ON DELETE CASCADE,
    PRIMARY KEY ("RoleId", "PermissionId")
);

-- 5. Audit Log (ghi lại thay đổi role)
CREATE TABLE "RoleAuditLogs" (
    "Id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    "UserId" UUID NOT NULL,                        -- User bị thay đổi
    "Action" VARCHAR(50) NOT NULL,                 -- 'role_assigned', 'role_removed', 'user_banned'
    "RoleId" INT,
    "PerformedBy" UUID NOT NULL,                   -- Admin thực hiện
    "Reason" TEXT,
    "CreatedAt" TIMESTAMP DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_user_roles_user ON "UserRoles"("UserId");
CREATE INDEX idx_user_roles_role ON "UserRoles"("RoleId");
CREATE INDEX idx_role_permissions_role ON "RolePermissions"("RoleId");
CREATE INDEX idx_audit_logs_user ON "RoleAuditLogs"("UserId", "CreatedAt" DESC);

JWT Token — Include Roles

// Services/TokenService.cs — Sửa logic generate token
public string GenerateToken(User user, List<string> roles)
{
    var claims = new List<Claim>
    {
        new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
        new Claim(ClaimTypes.Email, user.Email ?? ""),
        new Claim("fullName", user.FullName ?? ""),
    };
    
    // Thêm TẤT CẢ roles của user vào token
    foreach (var role in roles)
    {
        claims.Add(new Claim(ClaimTypes.Role, role));
    }
    
    var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_config["Jwt:Secret"]!));
    var token = new JwtSecurityToken(
        issuer: _config["Jwt:Issuer"],
        audience: _config["Jwt:Audience"],
        claims: claims,
        expires: DateTime.UtcNow.AddHours(24),
        signingCredentials: new SigningCredentials(key, SecurityAlgorithms.HmacSha256)
    );
    
    return new JwtSecurityTokenHandler().WriteToken(token);
}

Authorization Policies

// Program.cs — Đăng ký policies
builder.Services.AddAuthorization(options =>
{
    // Role-based policies
    options.AddPolicy("AdminOnly", policy => policy.RequireRole("SuperAdmin"));
    options.AddPolicy("EditorOrAbove", policy => policy.RequireRole("SuperAdmin", "Editor"));
    options.AddPolicy("TranslatorOrAbove", policy => policy.RequireRole("SuperAdmin", "Editor", "Translator"));
    options.AddPolicy("ModeratorOrAbove", policy => policy.RequireRole("SuperAdmin", "Moderator"));
    options.AddPolicy("AuthorOrAbove", policy => policy.RequireRole("SuperAdmin", "Editor", "Author"));
    
    // Permission-based policies (more granular)
    options.AddPolicy("CanManagePublications", policy => 
        policy.Requirements.Add(new PermissionRequirement("publications.create")));
    options.AddPolicy("CanManageUsers", policy => 
        policy.Requirements.Add(new PermissionRequirement("users.update")));
    options.AddPolicy("CanViewTransactions", policy => 
        policy.Requirements.Add(new PermissionRequirement("transactions.read")));
});

Custom Permission Handler

// Authorization/PermissionRequirement.cs
public class PermissionRequirement : IAuthorizationRequirement
{
    public string Permission { get; }
    public PermissionRequirement(string permission) => Permission = permission;
}

// Authorization/PermissionHandler.cs
public class PermissionHandler : AuthorizationHandler<PermissionRequirement>
{
    private readonly AppDbContext _db;
    
    protected override async Task HandleRequirementAsync(
        AuthorizationHandlerContext context, PermissionRequirement requirement)
    {
        var userId = context.User.FindFirst(ClaimTypes.NameIdentifier)?.Value;
        if (userId == null) return;
        
        // SuperAdmin bypass — có tất cả quyền
        if (context.User.IsInRole("SuperAdmin"))
        {
            context.Succeed(requirement);
            return;
        }
        
        // Check permission trong DB
        var hasPermission = await _db.UserRoles
            .Where(ur => ur.UserId == Guid.Parse(userId))
            .Where(ur => ur.ExpiresAt == null || ur.ExpiresAt > DateTime.UtcNow)
            .SelectMany(ur => ur.Role.RolePermissions)
            .AnyAsync(rp => rp.PermissionId == requirement.Permission);
        
        if (hasPermission)
            context.Succeed(requirement);
    }
}

// src/components/RequireRole.tsx
const RequireRole = ({ roles, children }) => {
  const { user } = useAuth();
  
  if (!user) return <Navigate to="/login" />;
  
  const hasRole = user.roles.some(r => roles.includes(r));
  if (!hasRole) return <Navigate to="/" />;
  
  return children;
};

🔄 10. Luồng nghiệp vụ theo Role

Luồng 1: Admin assign role cho user

1. SuperAdmin mở trang /users → tìm user 2. Click "Đổi Role" → modal hiện ra 3. Check thêm role "Translator" 4. Nhập lý do: "Tuyển dịch giả mới" 5. Submit → POST /api/admin/users/{id}/roles 6. Backend: - Insert UserRoles (userId, roleId=3, assignedBy=adminId) - Insert RoleAuditLog (action='role_assigned') - User mới login sẽ nhận JWT có thêm role "Translator" 7. Translator login Admin Panel → thấy menu "Dịch thuật"

Luồng 2: Author đăng truyện riêng

1. User request thành Author: - Client: nút "Đăng ký làm tác giả" → form thông tin - Hoặc: Admin assign role Author cho user 2. Author login → thấy menu "Author Dashboard" trên client 3. Author tạo Publication: - POST /api/author/publications (chỉ Author+ mới gọi được) - Backend auto-set: OwnerId = current userId 4. Author thêm chương: - POST /api/author/chapters (chỉ thêm cho truyện mình) - Backend check: publication.OwnerId == currentUser.Id 5. Revenue sharing (tương lai): - Khi user mua chương truyện Author → Author nhận % xu - Author dashboard hiển thị thu nhập

Luồng 3: Translator workflow

1. Translator login Admin Panel 2. Sidebar chỉ hiện: Dashboard (limited) + Dịch thuật 3. Translator vào /translation → thấy jobs "Waiting for Review" 4. Click vào job → review side-by-side (RAW vs Translated) 5. Sửa text blocks sai → "Re-typeset" 6. Approve chapter (hoặc Reject + ghi note) 7. KHÔNG THỂ: publish, tạo sách, xem users, xem tài chính → Nếu cố truy cập URL /users → redirect 403 "Không có quyền"

Luồng 4: Moderator xử lý report

1. Moderator login Admin Panel 2. Sidebar: Dashboard + Users (view+ban only) + Moderation 3. Vào /reports → thấy list reports pending 4. Xem report: "User X spam review trên truyện Y" 5. Action: - Xóa review vi phạm (DELETE /api/admin/reviews/{id}) - Ban user X (PATCH /api/admin/users/{id}/ban) - Dismiss report (nếu không vi phạm) 6. KHÔNG THỂ: sửa sách, quản lý tài chính, assign roles
