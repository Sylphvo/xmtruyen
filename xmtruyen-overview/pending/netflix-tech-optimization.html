2. CDN & Phân Phối Ảnh Truyện (Image Delivery)

2.1 Vấn đề hiện tại

  • Ảnh truyện tranh serve trực tiếp từ server .NET (port 5000) → bottleneck
  • User ở xa server → latency cao, ảnh load chậm
  • Không cache → mỗi lần mở lại cùng chương đều fetch lại từ server

2.2 Giải pháp: CDN Layer

2.4 Adaptive Image Quality (giống ABR cho ảnh)

📁 xmtruyen.API/Services/ImageOptimizationService.cs
/// <summary>
/// Serve ảnh theo chất lượng phù hợp với bandwidth/device của user.
/// Tương tự Adaptive Bitrate Streaming nhưng áp dụng cho ảnh tĩnh.
/// </summary>
public class ImageOptimizationService
{
    // Khi upload ảnh comic page → tạo 3 bản:
    public async Task<ImageVariants> ProcessComicPageAsync(string sourcePath)
    {
        return new ImageVariants
        {
            // Thumbnail: preview nhỏ cho danh sách chương
            Thumbnail = await ResizeAndConvert(sourcePath, width: 200, quality: 60, "webp"),
            
            // Medium: đọc trên mobile (tiết kiệm data)
            Medium = await ResizeAndConvert(sourcePath, width: 720, quality: 75, "webp"),
            
            // Full: đọc trên desktop (chất lượng cao)
            Full = await ResizeAndConvert(sourcePath, width: 1200, quality: 85, "webp"),
        };
    }
}

// Client chọn chất lượng dựa trên:
// - connection.effectiveType (4g/3g/2g) → JS Navigator API
// - screen width (mobile < 768px → medium, desktop → full)
// - user preference (tiết kiệm data toggle)
📁 xom-truyen/src/utils/imageQuality.ts
/**
 * Chọn chất lượng ảnh phù hợp dựa trên device + network.
 * Tương đương Adaptive Bitrate Streaming cho ảnh.
 */
export function getImageQuality(): 'thumbnail' | 'medium' | 'full' {
    // 1. Kiểm tra network (Navigator API)
    const connection = (navigator as any).connection;
    if (connection) {
        if (connection.effectiveType === '2g' || connection.saveData) return 'thumbnail';
        if (connection.effectiveType === '3g') return 'medium';
    }

    // 2. Kiểm tra screen width
    if (window.innerWidth < 768) return 'medium';

    // 3. Default: full quality
    return 'full';
}

3.2 Cấu hình Backend Worker xử lý ảnh

📁 xmtruyen.API/Services/Workers/ImageProcessingWorker.cs
using SixLabors.ImageSharp;
using SixLabors.ImageSharp.Processing;
using SixLabors.ImageSharp.Formats.Webp;

public class ImageProcessingWorker
{
    private readonly record struct ImageProfile(string Suffix, int MaxWidth, int Quality);
    
    private static readonly ImageProfile[] Profiles = new[]
    {
        new ImageProfile("thumb",  200,  60),
        new ImageProfile("medium", 720,  75),
        new ImageProfile("full",   1200, 85),
    };

    public async Task ProcessComicPageAsync(string inputPath, string outputDir, int pageNumber)
    {
        using var image = await Image.LoadAsync(inputPath);
        
        foreach (var profile in Profiles)
        {
            using var clone = image.Clone(ctx =>
            {
                // Resize giữ tỉ lệ
                ctx.Resize(new ResizeOptions
                {
                    Size = new Size(profile.MaxWidth, 0), // height auto
                    Mode = ResizeMode.Max
                });
            });

            var outputPath = Path.Combine(outputDir, $"page-{pageNumber:D3}_{profile.Suffix}.webp");
            
            await clone.SaveAsync(outputPath, new WebpEncoder
            {
                Quality = profile.Quality,
                FileFormat = WebpFileFormatType.Lossy
            });
        }
        
        // Tạo BlurHash cho progressive loading
        var blurHash = GenerateBlurHash(inputPath, componentX: 4, componentY: 3);
        // Lưu blurHash vào DB (ComicPages.BlurHash)
    }
}

4. Nén Ảnh: WebP, Progressive Loading & Image Tiling

4.1 WebP Encoding — Giảm 25-34% so với JPEG/PNG

Hiện tại: Ảnh truyện upload giữ nguyên định dạng gốc (PNG/JPEG) → dung lượng lớn.

Giải pháp: Auto-convert sang WebP trong Background Worker khi upload.

  • PNG → WebP Lossy (q85): giảm ~60% dung lượng
  • JPEG → WebP Lossy (q85): giảm ~25-34% dung lượng
  • Giữ Alpha Channel (ảnh nền trong suốt) khi cần
  • Fallback: serve JPEG cho browser không hỗ trợ WebP (IE11) — dùng <picture> tag

4.2 Progressive Loading — BlurHash / LQIP

📁 xom-truyen/src/components/Reading/ProgressiveImage.tsx
import React, { useState, useRef, useEffect } from 'react';

interface Props {
    src: string;           // URL ảnh full
    blurHash?: string;     // BlurHash string từ DB (4x3 components)
    width: number;
    height: number;
    alt: string;
}

/**
 * Hiển thị ảnh theo kiểu Netflix Progressive Loading:
 * 1. Hiện placeholder BlurHash (màu mờ, ~20 bytes inline)
 * 2. Load ảnh thật ở background
 * 3. Khi load xong → fade-in ảnh thật, fade-out blur
 */
export const ProgressiveImage: React.FC<Props> = ({ src, blurHash, width, height, alt }) => {
    const [isLoaded, setIsLoaded] = useState(false);
    const [isInView, setIsInView] = useState(false);
    const containerRef = useRef<HTMLDivElement>(null);

    // Lazy load: chỉ load khi vào viewport
    useEffect(() => {
        const observer = new IntersectionObserver(
            ([entry]) => { if (entry.isIntersecting) setIsInView(true); },
            { rootMargin: '200px' } // Preload trước 200px
        );
        if (containerRef.current) observer.observe(containerRef.current);
        return () => observer.disconnect();
    }, []);

    return (
        <div ref={containerRef} style={{ position: 'relative', width, aspectRatio: `${width}/${height}`, overflow: 'hidden', borderRadius: 4 }}>
            {/* Layer 1: BlurHash placeholder (inline, siêu nhẹ) */}
            {blurHash && !isLoaded && (
                <canvas
                    className="blurhash-canvas"
                    style={{ position: 'absolute', inset: 0, width: '100%', height: '100%', filter: 'blur(20px)', transform: 'scale(1.1)' }}
                    // Render blurHash via canvas (thư viện blurhash-js)
                />
            )}

            {/* Layer 2: Ảnh thật (lazy loaded) */}
            {isInView && (
                <img
                    src={src}
                    alt={alt}
                    loading="lazy"
                    onLoad={() => setIsLoaded(true)}
                    style={{
                        position: 'absolute', inset: 0,
                        width: '100%', height: '100%', objectFit: 'cover',
                        opacity: isLoaded ? 1 : 0,
                        transition: 'opacity 300ms ease'
                    }}
                />
            )}
        </div>
    );
};

5. Hệ Thống Gợi Ý Truyện (AI Recommendation)

5.1 Implicit Data — Thu thập hành vi đọc

/**
 * Thu thập dữ liệu hành vi ẩn (implicit signals) gửi về API.
 * Tương tự Netflix: track tốc độ xem, thời gian nán lại, thói quen bỏ dở.
 */
interface ReadingEngagement {
    userId: string;
    publicationId: string;
    chapterId: string;
    
    // Implicit signals:
    timeSpentSeconds: number;       // Thời gian đọc chương này
    scrollSpeedAvg: number;         // Tốc độ cuộn trung bình (px/s)
    pagesViewed: number;            // Số trang đã xem
    totalPages: number;             // Tổng số trang
    completionRate: number;         // % hoàn thành (0-100)
    didFinishChapter: boolean;      // Có đọc hết chương không
    didGoToNextChapter: boolean;    // Có chuyển chương tiếp không
    backtrackCount: number;         // Số lần cuộn ngược (đọc lại)
    sessionTimeOfDay: string;       // Khung giờ đọc (morning/afternoon/night)
    deviceType: string;             // mobile/desktop/tablet
}

// Gửi khi user rời chương (beforeunload hoặc navigate away):
export async function trackEngagement(data: ReadingEngagement) {
    await fetch('/api/engagement/track', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
        keepalive: true // Đảm bảo gửi được ngay cả khi tab đang đóng
    });
}

5.2 Recommendation Engine (đơn giản, không cần ML phức tạp)

📁 xmtruyen.API/Services/RecommendationService.cs
/// <summary>
/// Hệ thống gợi ý đơn giản dựa trên:
/// 1. Content-based: Truyện cùng thể loại/chủ đề user đã đọc
/// 2. Collaborative: "Người đọc truyện A cũng đọc truyện B"
/// 3. Engagement-weighted: Ưu tiên thể loại user đọc lâu nhất
/// </summary>
public class RecommendationService
{
    public async Task<List<Publication>> GetRecommendationsAsync(Guid userId, int count = 10)
    {
        // 1. Lấy thể loại user đọc nhiều nhất (weighted by time spent)
        var topCategories = await _db.ReadingHistories
            .Where(r => r.UserId == userId)
            .GroupBy(r => r.Publication.Categories.First().CategoryId)
            .OrderByDescending(g => g.Sum(r => r.TimeSpentSeconds))
            .Take(3)
            .Select(g => g.Key)
            .ToListAsync();

        // 2. Lấy sách cùng thể loại mà user CHƯA đọc
        var readIds = await _db.ReadingHistories
            .Where(r => r.UserId == userId)
            .Select(r => r.PublicationId)
            .Distinct()
            .ToListAsync();

        var recommendations = await _db.Publications
            .Where(p => !readIds.Contains(p.Id))
            .Where(p => p.Categories.Any(c => topCategories.Contains(c.CategoryId)))
            .OrderByDescending(p => p.ViewCount * 0.3 + p.AverageRating * 0.7) // Score
            .Take(count)
            .ToListAsync();

        // 3. Collaborative filtering đơn giản:
        // "Users đọc truyện X cũng hay đọc truyện Y"
        var collaborativeIds = await _db.ReadingHistories
            .Where(r => readIds.Contains(r.PublicationId) && r.UserId != userId)
            .Select(r => r.UserId)
            .Distinct()
            .Take(50) // Top 50 users có chung sở thích
            .SelectMany(uid => _db.ReadingHistories
                .Where(r => r.UserId == uid && !readIds.Contains(r.PublicationId))
                .Select(r => r.PublicationId))
            .GroupBy(id => id)
            .OrderByDescending(g => g.Count())
            .Take(count / 2)
            .Select(g => g.Key)
            .ToListAsync();

        var collaborative = await _db.Publications
            .Where(p => collaborativeIds.Contains(p.Id))
            .ToListAsync();

        // Merge và loại trùng
        return recommendations
            .Union(collaborative)
            .DistinctBy(p => p.Id)
            .Take(count)
            .ToList();
    }
}

6. Kiến Trúc Phần Mềm — Áp Dụng Cho Quy Mô Nhỏ

6.1 Từ Monolith → Modular Monolith (trước khi lên Microservices)

┌─────────────────────────────────────────────────────────────────┐ │ KIẾN TRÚC HIỆN TẠI (Monolith đơn) │ │ │ │ xmtruyen.API (1 project, tất cả controllers + services) │ └─────────────────────────────────────────────────────────────────┘ │ ▼ Refactor thành: ┌─────────────────────────────────────────────────────────────────┐ │ KIẾN TRÚC MỚI (Modular Monolith + Background Workers) │ │ │ │ ┌──────────────────┐ ┌──────────────────┐ ┌────────────────┐│ │ │ API Module │ │ Worker Module │ │ Scheduler ││ │ │ (Controllers) │ │ (Image Process) │ │ (Cron Jobs) ││ │ │ │ │ (Book Extract) │ │ (Stats calc) ││ │ │ Auth, Reading, │ │ (Recommendation │ │ (Cleanup old ││ │ │ Publications, │ │ score refresh) │ │ files) ││ │ │ Admin, Upload │ │ │ │ ││ │ └────────┬─────────┘ └────────┬─────────┘ └────────┬───────┘│ │ │ │ │ │ │ └─────────────────────┼──────────────────────┘ │ │ ▼ │ │ ┌──────────────────────┐ │ │ │ Shared Kernel │ │ │ │ (DbContext, DTOs, │ │ │ │ Interfaces) │ │ │ └──────────────────────┘ │ └─────────────────────────────────────────────────────────────────┘
💡 Netflix dùng Microservices vì có 1000+ engineers. Xóm Truyện quy mô nhỏ → dùng Modular Monolith: 1 solution .NET nhưng tách rõ modules. Khi scale lên mới tách thành services riêng.

6.2 High Availability cho quy mô nhỏ

  • Health Check endpoint: GET /api/system/health → trả về status các module
  • Auto-restart: NSSM tự restart service khi crash (đã có)
  • Graceful degradation: Nếu Recommendation service lỗi → hiển thị "Truyện phổ biến" (fallback static list)
  • Circuit Breaker: Nếu CDN lỗi → fallback về serve ảnh trực tiếp từ server
